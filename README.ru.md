# Hisense VIDAA (MT9603) — заметки по реверсу

Полевые заметки **только читающего** исследования телевизора Hisense с VIDAA
на чипе Mediatek **MT9603**: как устроен USB-контейнер прошивки, какие
локальные службы телевизор отдаёт веб-слою, как работает протокол моста
`phoenix://` и где именно стоит проверка прав.

Всё получено на своём устройстве, без его изменения. Образы прошивки не
распространяются, эксплойтов в репозитории нет: цель — документация
интерфейсов (исследование совместимости), а не взлом.

Английская версия: [`README.md`](README.md).

адреса локальной сети из репозитория удалены.

## Коротко

1. **USB-прошивка подписана RSA и зашифрована AES.** Заголовок: 256-байтный
   блок RSA по `0x000`, версия упаковщика `V_0.0.0` по `0x100`, директивы
   открытым текстом по `0x302`: `# REE_OFFSET_START = 0x1000 #` и
   `# REE_OFFSET_LEN = 0x3bec0000 #`. У нагрузки энтропия 7,9999–8,0000 по
   всему диапазону, ноль повторов 16-байтных блоков на выборке 64 МиБ, ни
   одной сигнатуры архива или файловой системы. Ключа в файле нет. В хвосте
   манифест открытым текстом: платформа, версия, SoC, производитель.
2. **Известные инструменты для MTK-пакетов не применимы.** `epk2extract`
   определяет пакеты Hisense по магику `hise` в нулевом байте — здесь там
   блок RSA. Его публичные «Mediatek generic»-ключи AES (Hisense/Sharp/TPV)
   дают мусор в ECB, CBC и CTR.
3. **Нет `Hisense_FileRead`, нет `File`, нет `Hisense_installApp`.** Мост
   отдаёт 96 функций, и все они — геттеры поверх `TvInfo_getParam`.
4. **Три локальные службы доступны из любого документа на телевизоре:**
   `https://localhost:9888/service/{pkgmgr,hiutils,tvinfo}`. Политика CORS
   разрешает читать их ответы с чужого origin.
5. **У `hiutils` короткий белый список**: `fileRead`, `fileWrite`,
   `deviceCode`, `uninstallApp`, `getVersionStatus`, `getOSVersion`. Всё
   привилегированное отвечает
   `503 client request permission check error, please check appconfig`.
   `fileRead` разрешён, но собирает путь от корня приложения, который для
   неустановленной страницы равен `undefined`.
6. **Идентичность из JavaScript не подделать.** Служба берёт её из нативного
   `vowOSContext`; `getIdentifier()` спрашивает `vowOSContext.getAppIdentifier()`,
   чей нативный `init()` для не-приложения возвращает `-1`. Подмена
   `navigator.appIdentifier` и `vowOSContext` меняет то, что отправляет SDK,
   но не то, что проверяет служба.

Итог: веб-слой даёт полную инвентаризацию моста и состояние служб, но не даёт
ни доступа к файлам, ни пути на запись. Дальше — только исполнение кода вне
веб-слоя (загрузчик/UART).

## Что в репозитории

```
docs/      разбор по темам, один файл на тему
samples/   очищенные выводы проб с устройства (JSON)
tools/     HTML-страницы проб, которыми это собрано (только чтение)
```

Страницы проб обращаются только к тому серверу, который их отдал
(`location.origin`), поэтому их можно положить на любой локальный веб-сервер.
Вызывают только чтение: ни `fileWrite`, ни `installApp`, ни удаления.

## Правовая рамка

- Декомпиляция для обеспечения совместимости разрешена в Германии по
  **§ 69e UrhG** (и ст. 6 директивы 2009/24/EC) для законного пользователя,
  когда информацию иначе не получить, и только в необходимой для
  совместимости части. Немецкий текст: <https://dejure.org/gesetze/UrhG/69e.html>
- Та же норма ограничивает передачу полученной информации третьим лицам.
  Поэтому здесь **наблюдения об интерфейсах** — форматы, имена api, схемы
  сообщений, коды ошибок, поведение — и **никаких извлечённых фрагментов кода
  или бинарников** прошивки вендора.
- Образ прошивки не распространяется. Контейнер описан размером, SHA-256 и
  раскладкой заголовка, чтобы каждый мог проверить свою копию, полученную от
  поддержки производителя.
- Никакого обхода DRM, обхода подписи обновлений и инструкций по снятию
  защит.
