# 2b. Что телевизор отдаёт в локальную сеть

Всё, что описано во [втором документе](02-local-services.md), доступно только
изнутри телевизора. Здесь обратный взгляд: что отвечает с другой машины в той
же сети.

## Порты

Проверялись поштучно, с паузой — про метод ниже:

```
открыт      36669   брокер MQTT
открыт      18400   UPnP / DLNA MediaRenderer
закрыт      9226    chrome inspect — отказ соединения
фильтруется 9223    CDP — не отвечает вовсе
закрыты     9222 9227 8080 8443 9443 8009 9009 9888
```

`9226` и `9223` — те самые отладочные интерфейсы, которыми в старых разборах
получали JavaScript в более привилегированном контексте, чем обычная страница.
На этой сборке `9226` сразу отказывает, а `9223` молча глотает пакеты. Значит
ни одного из них как точки входа нет, и идея «обойти гейт идентичности через
DevTools» на этой прошивке закрывается.

Порт `9888`, на котором живут службы веб-слоя, снаружи **недоступен** — он
слушает только loopback.

## 18400 — обычный UPnP без авторизации

Это стандартный DLNA MediaRenderer. Он объявляется по SSDP и описывает себя на
`/MediaServer/rendererdevicedesc.xml`. В дескрипторе есть блок `#CAP#` с
параметрами платформы — там и лежат интересные числа:

```
transport_protocol=3290   platform=1   voice=2   brand=his   vidaa_support=1   region=0
```

`transport_protocol=3290` — это маркер современного профиля аутентификации
VIDAA, по нему сторонние интеграции выбирают, какой MQTT-обмен пробовать.

Службы ровно три, все стандартные:

| Служба | SCPD | Управление |
|---|---|---|
| ConnectionManager:1 | `/MediaServer/cm.xml` | `/upnp/control/minguscmr` |
| AVTransport:1 | `/MediaServer/avt.xml` | `/upnp/control/mingusavtr` |
| RenderingControl:1 | `/MediaServer/rc.xml` | `/upnp/control/mingusrcr` |

Действия — ровно те, что описаны в спецификации DLNA: `GetProtocolInfo`,
`GetCurrentConnectionIDs`, `GetCurrentConnectionInfo`; `SetAVTransportURI`,
`Play`, `Pause`, `Stop`, `Seek`, `GetPositionInfo` и родственные;
`GetVolume`, `SetVolume`, `GetMute`, `SetMute`, `ListPresets`, `SelectPreset`.
Ни вендорских действий, ни нестандартных аргументов, ни недокументированных
полей.

SOAP-вызов проходит без всякой авторизации:

```
POST /upnp/control/minguscmr
SOAPAction: "urn:schemas-upnp-org:service:ConnectionManager:1#GetProtocolInfo"
→ 200, Source пустой, Sink — обычный список MIME
```

Два наблюдения, которые стоит сохранить.

Первое: `SetVolume`/`SetMute` и `SetAVTransportURI` — это запись без
аутентификации. Для DLNA-рендерера это норма, дороги к исполнению кода тут нет,
но любой в сети может менять громкость и подсунуть медиа-URL.

Второе: в списке принимаемых типов есть
`application/vnd.android.package-archive`. Рендереру незачем объявлять
поддержку APK — скорее всего это общая таблица MIME, скопированная из
платформы, а не намёк на установку пакетов. Записываю как странность, а не как
находку.

Файла `/upnp/description.xml` здесь **нет** — он отвечает 404. Единственный
дескриптор — тот самый MediaServer.

## Почему к списку портов нужна оговорка

Параллельный скан всех 65535 портов (400 потоков, таймаут 0,7 с) вернул
**пустой список**, и это неверно: тот же скрипт, запущенный поштучно с паузой,
показывает `36669` и `18400` открытыми меньше чем за миллисекунду. Телевизор
отбрасывает SYN-пакеты под нагрузкой, поэтому штурмовой скан даёт ложные
отрицания и публиковать его как результат нельзя. На этом устройстве
достоверны только поштучные проверки с паузой — полезно помнить, прежде чем
писать «у телевизора нет открытых портов» по быстрому скану.
