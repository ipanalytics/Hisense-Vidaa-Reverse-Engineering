# 2c. Единственный подтверждённый канал записи: `TvInfo_setParam`

Всё, что касается файлов, закрыто. Не закрыто одно — канал состояния. Страница,
отрисованная телевизором, может писать настройки устройства через нативную
функцию: без идентичности приложения, без проверки `appconfig` и без сессии.

## Как до него добраться

`TvInfo_setParam(key, value)` — глобальная функция рядом с `TvInfo_getParam`.
Сам SDK производителя использует её для меню настроек:

```js
vowOS.tvinfo.setBrightness = function (data) { return TvInfo_setParam('brightness', data) }
vowOS.tvinfo.setContrast   = function (data) { return TvInfo_setParam('contrast', data) }
```

Ничто не мешает странице вызвать функцию напрямую с любым ключом.

## Какие ключи живые

Проверялось чтением ключа и записью **того же значения** обратно: для
устройства это пустая операция, но видно, принимает ли сеттер ключ вообще.

| ключ | значение на устройстве | запись |
|---|---|---|
| `brightness` | 50 | принята |
| `contrast` | 80 | принята |
| `kidsMode` | 0 | принята |
| `storeMode` | 0 | принята |
| `isHotelMode` | 0 | принята |
| `magnificationEnable` | 0 | принята |
| `ttsEnable` | 0 | принята |
| `panelType` | 0 | принята |
| `region` | `EU_A` | принята |
| `featureCode` | вырезано | принята |
| `artMode`, `hotelMode`, `dabTools`, `volume`, `mute`, `country`, `source`, `menuScheme`, `menuTransparency` | `null` | ключа нет |

Десять живых сеттеров, девять имён, которых не существует. Это состояние, а не
файлы — но в списке есть `isHotelMode`, `storeMode` и `region`, то есть ровно те
настройки, которые обычно требуют сервисного меню.

## Почему это важно

Это единственный путь записи на этой прошивке, подтверждённый для произвольной
веб-страницы. Он идёт не через гейт `appconfig`, а мимо него: гейт накрывает
`hiutils` (`fileWrite`, `deviceCode`, `uninstallApp`), а `TvInfo_*` — отдельная
нативная поверхность, которую проверка прав не оборачивает.

Практические следствия:

- Страница может переключить shop/store-режим и hotel-режим без всякой
  идентичности. Для устройства, которое стоит в сети с браузером, это
  конфигурационный риск.
- Вместе с находкой про регистрацию в websocket (см.
  [четвёртый документ](04-identity-gate.md)) это показывает, что модель прав
  здесь по-сервисная, а не по-устройственная: `hiutils` заперт, `tvinfo` — нет.
- Файловой системы это по-прежнему не касается. Чтение `/etc/*` и запись файлов
  остаются за той же стеной.

## Что сознательно не трогалось

`isHotelMode` и `region` не менялись. Записать то же значение обратно безопасно,
а записать другое — неочевидно обратимо через интерфейс: hotel-режим известен
тем, что запирает пользователя, когда пункт выхода пропадает из настроек на
моделях не линейки HL, а `region` влияет на то, что платформа считает себе
позволенным показывать. Механизм описан здесь, чтобы им можно было
воспользоваться осознанно, зная, что тот же вызов возвращает всё назад.
